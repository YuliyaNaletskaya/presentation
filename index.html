Micro Frontend

How we came to the micro frontend

  1. Monolith architecture: for projects managed by one team with databases, backend, and frontend shared
  2. Separated backend and frontend development
  3. Frontend development separated in isolated parts
  4. Micro frontend: an application is split into isolated, self-managed parts

What is Micro Frontend

A design pattern in software architecture where the user interface (UI) of a web application is broken down into smaller parts for more manageable parts known as micro front-ends.

https://www.geeksforgeeks.org/what-are-micro-frontends-definition-uses-architecture

Micro Frontend Advantages

  • Scalability: You can independently scale parts of the front end
  • Team Autonomy: Different teams - different technologies
  • Reusability: Modules reusable across multiple projects
  • Improved Maintenance: Small and more focused modules - more manageable maintenance
  • Faster Development: parallel development, allows teams to release features independently and bring them to market faster
  • Easier Migration: Possibility of migrating gradually

Micro Frontend Architecture

A collection of small, self-contained frontend modules each responsible for a specific part of the user interface.

Permits independent Development, testing and deployment.

Key components

  • Module Composition: each module represents a different feature or functionality
  • Integration Layer: responsible for combining individual modules into a symmetric user interface
  • Careful Routing and Navigation

    are crucial and can be achieved using techniques like URL routing, event-based communication, or centralized routing services

  • Communication:

    data exchange or trigger actions can be established using techniques like pub-sub messaging, shared state management, or RESTful APIs

  • Deployment and Orchestration: Independent deployment of every module
  • Orchestration tools:

    Kubernetes or Docker Swarm

Micro Frontends Disadvantages

  • increasing the web app’s payload size
  • hard to maintain communication (between micro frontends)
  • separate teams working on each micro frontend create pages inconsistent in terms of style, and UX/UI
  • a lot of repositories, tools, more build/deploy pipelines, and more complex infrastructure

Micro Frontends could perfect for:

  • Medium or large projects
  • Projects there high productivity is needed

Don’t use Micro Frontends if:

  • Your project size is small
  • You have a high risk of poor communication between teams
